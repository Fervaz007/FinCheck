## Why

FinCheck grew into nine overlapping sections (Recurrentes, Compromisos, Categorías, Deudas, Presupuesto...) that all try to answer the same question in different, disconnected ways: "how much do I owe, when, and does it fit my budget?" Debts, their recurring payments, and the biweekly reserve math live in three separate screens that don't talk to each other, categories exist but never actually feed the one calculation they were meant for, and every income/expense/debt entry asks for a bank account even though the user only ever looks at one number: total money available. This change consolidates those sections around the user's actual mental model — one pool of available money, and debts (not categories) as the unit that carries a budget-rule type — and removes screens/fields that no longer do real work.

## What Changes

- **BREAKING**: Remove the "Recurrentes" screen. Recurring debt/bill payments move into "Deudas"; recurring income moves into "Movimientos" (income form gets an "¿Es recurrente?" check reusing the existing recurrence engine).
- **BREAKING**: Remove the "Compromisos" screen, the `commitments` table, and its DAO/service/hook. Replaced by automatic per-debt reserve accrual (see new "Apartados" screen below).
- **BREAKING**: Remove the "Categorías" screen, the `categories` table, and all `categoryId` columns/usages. Categories never actually drove the budget-compliance calculation (`computeBudgetCompliance` used hardcoded group names); the "type/group" concept moves to debts instead.
- **BREAKING**: Remove the independent debt-limit setting (`settings.debtLimitPct` as a user-edited field) and the "¿Cuánto separar de este ingreso?" tool in Presupuesto. In its place, any number of allocation rows in a budget rule can be marked "monitorear este grupo" — each monitored row gets its own occupied-vs-limit tracking on Inicio, and overall financial health status is the worst status across all monitored rows (not debt-specific).
- **BREAKING**: Remove the "Cuentas" screen and the `accounts` table entirely — not simplified, deleted. There is no declared-balance concept at all: the user never used it (money gets tracked by logging income, not by declaring a balance). Income keeps a purely descriptive **origin** field — free text the user types directly (e.g. "Efectivo", "TDD", "Préstamo personal"), with no backing table or fixed catalog, never used in any calculation; expenses and debt payments reference no account/origin at all.
- New "Deudas" flow: every debt (parent or standalone) is created with a **Tipo** (one of the active budget rule's allocation labels), a **Periodicidad** (`mensual` or `bimestral`), an **¿Es recurrente?** flag, a payment day, and a starting **Apartado inicial**. Child debts are unchanged (name, monthly payment, remaining months) and inherit type/periodicity/day from their parent conceptually (they don't carry their own). Registering any debt requires only an active budget rule (to source Tipo options) — otherwise the app blocks it with an explanatory message. No monitoring designation is required to create a debt.
- Removes the old "pago automático" concept (day + account picked at debt creation). Recurrence is now just the `¿Es recurrente?` flag; no account is ever picked for a debt, at creation or at payment confirmation.
- New **"Apartados"** screen: shows only parent and standalone debts (never children) that are recurring. Each accrues automatically every time a biweekly cutoff (15th / last day of month) is crossed since the app was last opened — 1/2 of the amount per cutoff for `mensual`, 1/4 for `bimestral` — reusing the existing catch-up reconciliation pattern. The accrual resets to $0 only when the user confirms that debt's payment (no separate manual reset).
- Presupuesto: rule creation/activation stays, but the ad-hoc "+ Usar 50/30..." preset button is removed (rules can only be created through the dedicated Reglas Presupuestarias flow), and the existing-rules list gets a clearer, non-cramped layout (also applies to Reglas Presupuestarias). Per-group compliance ("ocupado / límite" per budget-rule type) moves from Presupuesto into Inicio, shown only for monitored types, computed from real debt totals per type instead of hardcoded group names.
- Reglas Presupuestarias: existing rules can now be edited (name, allocations, monitored flags) and deleted (blocked while a rule is active, to avoid leaving the app with no active rule).
- Simulador gains a contado/a-meses toggle and a Tipo selector; "a meses" validates against that type's remaining capacity under the active rule, "a contado" validates against real available money.
- Inicio (Dashboard) keeps its current layout except: adds per-type compliance, and drops/reworks the "Saldo real / Saldo proyectado" card since it depended on per-account ledgers that no longer exist.
- Inicio gains a prominent, month-independent **"Disponible" global** (all income − all expenses − all confirmed debt payments, across all dates) above the month navigator — fixing that money entered in a prior month vanished from view when the month rolled over. The per-month card's net row is relabeled "Balance del mes" so it isn't confused with the global figure. The global total does not subtract reserve accruals.
- Configuración gains a **"Borrar todos los datos"** action (full factory reset of every table, back to first-launch state) behind an explicit destructive confirmation — needed to re-validate from scratch after all these structural changes.

## Capabilities

### New Capabilities
- `debt-reserves`: automatic biweekly reserve accrual per recurring parent/standalone debt ("Apartados") — replaces manual commitments entirely.
- `data-reset`: a full factory reset of all user data from Configuración, behind a destructive confirmation.

### Modified Capabilities
- `debts`: adds Tipo (budget-rule allocation label), Periodicidad (mensual/bimestral), ¿Es recurrente? flag, starting reserve amount; removes the pago-automático (day+account) concept and any account reference on payment confirmation; requires only an active rule before a debt can be created (never a monitored row — monitoring is a display/health concern, not a creation gate).
- `budget-rules`: allocation rows gain a "monitorear este grupo" designation (any number per rule, not just one); rule creation is the only place rules can be created (no ad-hoc presets elsewhere); existing rules can now be edited and deleted; existing-rules list gets a clearer UI.
- `recurring-transactions`: recurring debt payments are now configured from within Deudas (via the ¿Es recurrente? flag) instead of a standalone Recurrentes screen; recurring income is configured from within Movimientos' income form; the dedicated Recurrentes screen is removed.
- `income`: income entries gain an optional "¿Es recurrente?" flag (with frequency) and a free-text **origin** field (no longer an account picked from a table) that is purely descriptive (not used in any balance calculation).
- `expenses`: expense entries no longer reference an account or a category.
- `dashboard`: adds per-budget-rule-type compliance (occupied vs. limit); removes the real/projected balance card; adds a global, month-independent "Disponible" as the primary figure and relabels the per-month net as "Balance del mes."
- `purchase-simulator`: adds a contado/a-meses mode and a Tipo selector that changes which capacity the simulation checks against.
- `financial-health`: overall status is now the worst status across every monitored budget-rule group (not just debt) — see `budget-rules`' monitoring flag; savings ratio input can no longer be derived from category tagging and is dropped (see design.md).

### Removed Capabilities
- `categories`: fully removed — the screen, table, and all `categoryId` references.
- `commitments`: fully removed — replaced by `debt-reserves`.
- `accounts`: fully removed — the "Cuentas" screen, the `accounts` table, and its DAO/hook. There is no declared-balance concept; income's account tag becomes free text (see `income`).
- `debt-limit`: fully removed — a single designated "debt limit" row is superseded by `budget-rules`' generalized per-row monitoring, consumed by `financial-health` and `dashboard`.

## Impact

- **Schema**: `src/db/schema.ts` — drop `categories`, `commitments`, `accounts` tables; drop `categoryId` from `income`/`expenses`/`recurringTransactions`; drop `accountId` from `expenses`/`debtPayments`; change `income.accountId` (FK) into a free-text nullable `origin` column; add fields to `debts` for type/periodicity/recurring flag/reserve tracking; add an `isMonitored` boolean (any number per rule) to `budgetRuleAllocations`; drop `settings.debtLimitPct` as a directly-edited field.
- **Screens**: remove `categorias.tsx`, `compromisos.tsx`, `recurrentes.tsx`, `cuentas.tsx`; add `apartados.tsx`; rework `deudas.tsx`, `movimientos.tsx`, `presupuesto.tsx`, `simulador.tsx`, `reglas-presupuestarias.tsx` (add edit/delete), `index.tsx`; update `src/app/(drawer)/_layout.tsx` drawer entries (remove Cuentas, Compromisos, Recurrentes; add Apartados).
- **DAOs/services/hooks**: remove `categoriesDao`, `commitmentsDao`, `accountsDao`, `services/financial/commitments.ts`, `services/financial/debtLimit.ts`, `hooks/useCategories`, `hooks/useCommitments`, `hooks/useAccounts`, `hooks/useDebtLimit` (all dead/superseded — see design.md decision #8); update `debtsDao`, `expensesDao`, `incomeDao`, `budgetRulesDao` (add update/delete), `debtPaymentsDao`, `services/financial/budget.ts`, `services/financial/health.ts` (multi-group status), `services/financial/simulator.ts`, `services/recurring/reconciliation.ts`, `hooks/useDashboardSummary.ts`, `hooks/useDebts.ts`.
- **New**: a debt-reserve accrual mechanism analogous to `recurrenceOccurrences`/`runReconciliation` but for reserve accumulation instead of transaction generation.
- **New (dashboard global total)**: all-time sum helpers for income/expenses/confirmed debt payments feeding a month-independent `globalAvailableCents`; `useDashboardSummary.ts` and `index.tsx` updated.
- **New (data reset)**: a reset routine that empties every table (FK-safe order), wired to a confirmed destructive action in `configuracion.tsx`.
- **Bug fix (found during manual testing of the implemented change)**: the app's drawer navigator keeps every visited screen mounted; no data hook refetches on refocus (`useFocusEffect` is used nowhere in `src/`). This let a screen keep showing stale data (e.g. Deudas not noticing a budget rule was activated from another screen) after navigating away and back. Needs `useFocusEffect`-based refetching added to the affected hooks (at least `useBudgetRules`; audit others used across screens).
- **Tests**: `src/services/financial/__tests__/commitments.test.ts` removed; `debtLimit.test.ts`, `health.test.ts`, `budget.test.ts`, `debtHierarchy.test.ts`, and `src/dao/__tests__/debtPaymentsDao.integration.test.ts` need updates for the new signatures/behavior; any test seeding/referencing the `accounts` table needs updating.
